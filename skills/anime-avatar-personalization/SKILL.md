# Anime Avatar Personalization

## 输入与目标

请用户**给 agent 提供一个可用的二次元风格 VRChat Avatar，最好是头部贴近目标的**，并提供目标角色图或文字要求。使用用户有权使用、可编辑的 Avatar 工程/资产；单个 VRChat 角色 ID 不足以执行网格和控制器适配。

基于现有 Avatar 的可动画头部和颈部定制身份，分别生成/适配头发与穿衣身体，再统一骨架和控制。模板品牌、骨路径、组件编号和软件安装位置均由当次输入决定。本 skill 不附模型资产或通用自动绑定程序；不要把方法指导当作已经运行成功的生成管线。

先识别本次要完成的是脸部、头发、身体装配、组合动画还是完整平台交付。用户已接受的外观作为后续约束，未涉及的部分继续复用。不要为了遵循完整流程而重做用户未要求更改的部件。

## 建立本次工作契约

1. 核对模板能实际运行眨眼、眼球转动和口型，记录原缺陷。清点真实头颈网格、shape/帧、UV、骨架、生产控制器和 descriptor；保留源副本。
2. 固定角色身份、正面轮廓、非对称饰品物理侧、身高/头身比及衣领等不可破坏项。文字输入先形成明确视觉目标；隐藏侧面/背面标为推测。
3. 记录可用 ImageGen、三维生成服务、Blender、Unity、SDK/shader 及实际版本。采用可用工具，先完成输入和运行条件核验，再执行对应步骤；缺失工具或资产时明确缺口。
4. 新建本角色本地任务目录；原始输入、批准目标、候选、标定、输出和证据分别保存。云端任务记录已授权的候选范围/预算；达到预算或重复相同结构失败时回到参考/结构诊断。

可复制 [角色工作表](references/worksheet.md) 记录本次参数、结果和人工干预。它是待填写的执行记录，初始状态不是通过。

## 按任务读取对应指南

- **脸部、眼珠、眉毛、睫毛、眨眼/口型：**读 [face.md](references/face.md)。优先复用模板拓扑和形态；需要新睫毛时使用 ImageGen 图案、眼孔注册和局部闭合修正。
- **头发生成、静态适配、骨链/代理权重/物理：**读 [hair.md](references/hair.md)。先冻结静态轮廓，再做逻辑发束分组与真实 SDK 对照。
- **身体生成、完整头颈移植、领口保护、骨架统一：**读 [body-assembly.md](references/body-assembly.md)。生成参考时就准备接口；生成皮肤与衣领必须按语义分离。
- **单项回归、组合预览、平台输入与交付：**读 [validation.md](references/validation.md)。结构保真、实际运动和原材质外观分别验证。

完整角色任务的推荐顺序为：参考规格 → 模板基线 → 脸部及动画 → 头发静态 → 发束物理 → 身体及绑定 → 头颈装配 → 保存重开 → 组合测试 → 按交付范围进行客户端验证。身体参考可提前准备；上游修改后重新测试受影响部分。

## 关键适配约束

- **保持动画先验。** 保留原头颈的眼球、眼睑、口腔、表情、viseme 和骨路径。换材质、保留 shape 数量或 FBX 导出成功都不证明动画兼容。
- **锁定已接受的外观。** 不擅自撑大眉眼上方发壳、抬短刘海或改衣领来掩盖穿插；定位局部结构并另存候选。
- **图案与变形分工。** 睫毛/外观贴图使用 ImageGen 或用户提供的实际图像；适配程序可生成 UV 选区、承载面、形变及裁切控制，不自行画替代睫毛轮廓。生成的过程图只作目标，仍需同拓扑对应与接触验证。
- **完整头颈接口。** 优先刚体安放已验证头颈，只修剪埋入衣领的颈底；不得把头颈皮肤与白色领子一起水平切掉。
- **绑定是实际三维计算。** 骨架、bindpose、权重与静止表面一起核验。T-pose 若用于 Humanoid 参考，保存前恢复原生成姿态。
- **物理写入单一。** 用实际 SDK PhysBone 或目标平台对应组件驱动发骨；动画/观察脚本不同时写这些骨。按当前平台分别测试，不把另一物理引擎结果当作 SDK 证据。
- **不继承旧证据。** 新几何、权重、控制器或运行材质变化后重做相关回归。语义部件号、毫米余量、裁切像素、链数和物理参数均重新标定。

## 运行与完成标准

使用实际可用的固定环境，按任务大小设置资源保护并优先串行重任务；不把某台机器的内存阈值当成普遍需求。保留失败和版本，不覆盖源资产。没有本地生成需求时无需安装无关权重或训练环境。

输出实际保存的工程/资产索引、输入与最终 hash、必要标定、全身四面/脸部近景、原生连续组合预览，以及分项 `PASS / PARTIAL / FAIL / NOT RUN`。明确人工修形/修权重、推测结构、近似口型、显式眼动、诊断接地及未测平台能力。

“能动”“碰撞体外的有限抽样无穿插”“连续视频编码成功”分别说明各自证据范围。完成 VRChat 交付需要当前版本实际的 SDK 输入、Build & Test、本地试穿和性能记录；发布 Avatar 为单独的用户授权动作。
