# 脸部、UV、眉睫与连续面部驱动

适用于用户已提供可用二次元 VRChat Avatar 的脸部定制。保持该 Avatar 的面部结构先验，按目标差异选择需要执行的步骤。主入口见 [SKILL.md](../SKILL.md)。

## 1. 模板检查与身份目标

先在原生环境实际查看中性、九方向视线、普通/笑眼半闭和全闭、左右单眼、嘴型及组合。记录原模已有的闭合交叉、漏眼和控制冲突，避免把它们全归因于定制。

保护的契约包括：

- Face/Neck renderer 路径、网格/材质、submesh、全部 UV、法线/切线。
- 骨路径、静止矩阵、bindposes、每个顶点的全部影响权重。
- shape 名称、所有帧权重与 DV/DN/DT、默认预设、原 Eye Look/viseme 引用。
- 根 Animator 的生产层、mask、Write Defaults、状态/转换和曲线绑定。

统一相机、瞳距与中性视线后比较脸型；二维插画没有三维真值时，隐藏结构用模板先验并标记为推测。

从目标中明确虹膜/瞳孔/高光是否分层，眉毛形状、上睫毛黑带与拖尾、眼孔曲率、下颌和鼻口位置。优先选头部贴近目标的模板，减少拓扑与闭合运动之间的冲突。

## 2. ImageGen 目标与受约束的 UV 烘焙

先生成/确认脸部目标，再做 atlas 候选。可按实际输入调整提示：

```text
以角色参考为身份和色彩依据，以所提供模板裸脸为三维比例依据。
保持中性姿态、视线和相机，匹配虹膜渐变、独立瞳孔、高光、眉毛及上睫毛。
分别呈现普通闭眼和笑眼，不把两者画成同一条曲线。
目标连续黑色睫毛带要有足够遮挡宽度，不替换成几根细长毛。
不修改未要求更改的部位，不增加多余妆容或结构。
```

制作 atlas 候选时提供原图集及语义岛说明：保持原布局，独立瞳孔存在时虹膜不再画第二个瞳孔；避免生成器把独立高光/睫毛烘焙进皮肤。

落地步骤：

1. 用网格连通分量、submesh 和 UV 三角形清点皮肤、耳、眉、虹膜、瞳孔、睫毛片；审核语义，不依赖组件编号。
2. 基于原 UV 生成允许修改的遮罩，按实际分辨率设置 padding，保护皮肤接缝边界。
3. 仅将生成候选的外观采到授权区域。保留原 atlas 的 alpha 和选区外通道；生成器移动过的 UV 岛不能直接取代原布局。
4. 保留模板连续遮挡核心。目标睫毛过细时重新生成足够粗的参考/纹理；提示词本身不等于实际遮挡保证。
5. 明确 importer 的颜色空间、压缩、mipmap、alpha 与 shader 设置。原像素相同不保证不同采样设置下显示相同。

RGBA 图案应来自 ImageGen 或用户素材。几何、UV mask 和诊断标色可以由程序计算；不要画替代睫毛 alpha 来冒充生成结果。

## 3. 脸型、眼珠与眉毛

先使用原作者的脸型、眼距、眼型、鼻口和下颌形状参数；分别保存不同强度候选。每次同时检查正面、45°、侧面与闭合状态。

独立瞳孔、虹膜和高光应各自保留其结构和动画。需要改瞳孔图案时，按其原 UV 形状归一化再映射目标采样区；不要将同一图案同时印到虹膜与独立瞳孔上。眉毛形变范围与眼睑/额头形变范围分开确认。

若必须对模板作非线性身份变形 `W`，表情位移也要迁移。对点 `p` 和源表情 `d`：

```text
d_target = W(p + d) - W(p)
```

只有原基态变形而原 shape 位移不变，可能破坏眼睑/嘴角接触。完整帧迁移后，在未参与构造的中间权重测试；必要时加入中间权重修正帧，记录误差和原数据变化。不要为简单风格调整先重做整个脸部拓扑。

## 4. 决定是否替换上睫毛

原睫毛接近目标时，保留原拓扑/形变、仅改受约束外观。原轮廓与目标明显不符时再使用独立 ImageGen 睫毛。

新的透明 RGBA 生成目标需明确：连续上黑带、内外端、拖尾的范围和厚度；不带眉毛、皮肤、眼白或额外下眼线。检查实际输出是否匹配指定区域，而非只看整体“像睫毛”。

采用通用 UV 网格作为承载面，实际可见轮廓由生成 alpha 决定：

1. 提取原皮肤眼孔上下边界、内外眼角；不要把泪阜侧壁最低点当成上缘内端。
2. 提取生成主带内缘并逐列注册到上眼睑。承载面可以含透明区，不把整个矩形当作可见面。
3. 以小范围重叠和深度余量处理肤色细缝，同时检查斜面悬浮。毫米值按模板尺度测量。
4. 使用眼睑对应三角形的重心坐标转移蒙皮/表情帧；明确需要局部坐标系运输的偏移。
5. 处理原默认身份 morph 对新载体的重复影响；保留源顶点与帧数据的可核验对应。

先冻结接受的全睁眼外观，再处理半闭/闭眼。新卡片继承原 shape 也不会自动获得正确的动态轮廓。

## 5. 有效闭合与普通/笑眼分路

多个闭合通道简单相加会重复闭合。归一化双眼输入 `b`、左右单眼 `uL/uR` 在 `[0,1]`，可采用平滑有界合成：

```text
cL = 1 - (1 - b) * (1 - uL)
cR = 1 - (1 - b) * (1 - uR)
```

先核验原模板双眼与左右单眼形态的关系，再决定采用这条组合规则。笑眼往往自身已闭眼，需要独立造型路径与 blink/joy 组合补偿；不能把普通闭眼终点机械当作笑眼。

修正应由持久化 Animator/目标平台驱动实现，观察脚本记录实际值。新层写入原通道时明确覆盖规则；不要在不含相关表情的空状态中盲写 helper=0，覆盖先前有效层。

## 6. 眼睑接触、主带与局部拖尾

目标是保留全睁眼、同时改善中间态和闭合：

- 正常全睁基态的新增修正为零。
- 上下皮肤眼孔边界渐向共同三维接合曲线靠拢；位移局部衰减，不牵动眉毛/整个额头。
- 查询实际眼球/皮肤三角形前表面，不用不合适的球体近似替代所有二次元眼球。
- 主黑带可保厚，拖尾独立旋转/收短；是否整带变薄由目标决定。

一种局部拖尾拟合表达为：

```text
x(c) = r(c) + (1-c) * R(c) * (x_open-r_open)
```

`r(c)` 为运动根部，`R(c)` 由该眼的眼角/眼睑方向变化拟合。围绕共同根部收回，避免每列独立根部使不可见拖尾仍有大范围残留。表面投影和末段裁切会令实际可见长度不严格线性。

在同拓扑/UV 上拟合多个正常/笑眼关键形态，分别保存左右眼残差，用标准多帧 blendshape 连续插值。关键点数量由形变复杂度决定；检查关键点间的未拟合姿态。旋转插值可用于局部坐标框，不能直接用 slerp 替代三维表面对应和眼睑接触。

如果粗网格在收尾阶段留下残片，可用连续材质裁切消除末段；材质参数与有效闭合值同步，检查最后几帧闪变。不要恢复“睁眼把旧遮挡层藏起来、闭眼重新长出”的策略。

**接触约束需准确命名。** 皮肤/眼球前包络可能主要是皮肤，不等于贴眼白。分别测拖尾内缘到可见眼孔/眼白边界、深度间隙和穿插；保留睁眼几何可能限制深度修正，应报告取舍。

## 7. 尖片、亮折痕与生成多阶段图

用 alpha 连通分量定位多余分离片，确认语义后在复制材质/载体上处理显示范围，保留原 ImageGen 图。不要对不同图直接复用固定像素阈值。

亮折痕先用组件/材质隔离与原生深度定位：来源可能是旧半透明覆盖层、穿面、法线或光照。修改实际致因；删掉某层时记录失去的表情效果，不把局部删除规则推广到全部模板。

ImageGen 多阶段图用于提供美术约束。生成后检查每格身份、普通/笑眼方向、眼孔高度、睫毛范围与曲率；提示“25% 闭眼”不代表实际几何量。若阶段不一致，先修目标再拟合；运行时切图或像素淡化不能自动解决侧视、皮肤闭合和遮挡。

## 8. 完成此阶段的证据

保留同输入的前后比较、全睁眼锁定检查、九向视线×三闭合、左右单眼与重叠过渡、正常/笑眼连续周期、眉毛/viseme 组合、转头和复位。源顶点/shape 保护按允许变化核验。

眼球 ID 诊断可检测眼白/虹膜/瞳孔暴露；只数某种颜色可能漏判。诊断零像素仅支持具体视角的遮挡，仍要看原材质轮廓、折角和穿插。

最终交接头颈资产、实际材质/控制器、关键形态和标定索引、源/最终 hash，以及已通过/未过的状态。显式输入可动与 SDK 自动眨眼/音频/跟踪接通分别记录。继续按 [validation.md](validation.md) 做组合验证。
